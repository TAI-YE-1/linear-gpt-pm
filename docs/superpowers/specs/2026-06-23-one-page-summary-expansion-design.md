# 一页纸考核材料扩写设计

## 目标

将 `outputs/latest/one_page_summary.md` 从摘要级内容扩写为可在一页内快速阅读的结构化考核材料。目标篇幅为约 900–1200 个中文字符；篇幅以信息完整、排版可读为准，不为凑字数重复表述。

## 内容结构

文档保留并扩展以下七个部分：

1. 项目背景：说明业务场景、涉及的 AI 工具和相关项目类型。
2. 原始问题：明确需求边界、修改范围、验收和复盘缺失带来的风险。
3. 方法设计：分别说明 OpenSpec、Superpowers、Codex 与 Git 证据的职责。
4. 执行过程：以 Explore、Propose、Subagent Plan、Apply、Verify、Review、Archive 描述闭环。
5. 交付成果：基于已有事实说明 `order-helper.html` 的离线功能与交互输入输出。
6. 验证与改进：仅陈述可由需求、计划、差异和测试记录支撑的过程性价值；不添加未经证实的量化指标。
7. 复用价值：明确适用于后续同类开发或修复任务的范围和边界。

## 表达约束

- 中文为主，保留文件名、工具名和流程阶段的英文名称。
- 使用短段落和少量列表，便于一页呈现与口头讲述。
- 不改动代码、输入材料、生成逻辑或其他输出文件。
- 不虚构测试通过率、效率提升比例、用户数据或生产结果。

## 验收标准

- `outputs/latest/one_page_summary.md` 覆盖上述七类信息。
- 内容能对应仓库中的实际流程文件和已有交付描述。
- 文档保持单个 Markdown 文件，且无占位符、重复段落或无依据的结论。
- 变更范围仅包括目标一页纸及本设计记录。
