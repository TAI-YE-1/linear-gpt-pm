# Reuse Guide

The Skills are project-independent. Reuse should require changing context, not editing Skill rules.

## Inputs to provide per project

- project name and purpose;
- authoritative Linear projects or current structure;
- responsible people and decision authority;
- status conventions and review cadence;
- optional software repositories;
- explicit exceptions such as approved operational maintenance.

## Recommended adoption

1. Inspect the existing structure.
2. Adapt rather than overwrite.
3. Run one real intake and one real audit.
4. Correct ambiguous rules or project-specific exceptions in the project's own documentation, not in the shared Skill.
5. Configure automation only after the manual workflow is stable.

## Evidence of successful reuse

A second project should use the same installed Skills without changing their source. Only project context, Linear targets, optional repositories and cadence should differ.
