# Scenario Cases

## Governance

1. Historical user report without current reproduction → create Q/investigation candidate, not confirmed PROB.
2. New instruction materially changes accepted requirement → create CR and identify affected tasks.
3. User explicitly approves exact writes → execute without redundant confirmation and read back.
4. Linear is read-only → return candidates and exact write plan; do not claim completion.
5. Bulk setup conflicts with existing labels → propose adaptation; do not duplicate silently.

## Audit

1. Execution task without source relation → High exception.
2. Done task with only a textual completion claim → evidence exception.
3. Canceled requirement with active implementation → consistency exception.
4. Answered Q remains open → closure exception.
5. Linear claims deployment while GitHub evidence is inconclusive → report conflict and limitation.
6. No GitHub connection → audit Linear evidence only; do not claim code verification.
7. Automated run → may write only the authorized report artifact.
