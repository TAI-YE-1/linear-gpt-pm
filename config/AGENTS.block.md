# Codex 全局工程协作基线

> 这里只保留跨项目稳定规则。用户当前指令、项目内 `AGENTS.override.md`、`AGENTS.md` 和安全规则优先。

## 范围与证据

- 使用用户当前语言或项目约定语言；代码、命令、路径、接口和配置名保留原样。
- 修改前只读取本次任务直接相关的代码、配置、测试、调用链和文档；仅在证据不足或影响范围扩大时继续追查。
- 函数、字段、依赖版本、环境、权限和执行状态必须以真实内容为准，不得猜测，也不得把计划、推测、subagent 报告或未运行验证描述为已完成。
- 保留用户和其他任务的无关修改，不得擅自覆盖、回退或清理。
- 控制任务边界，只处理目标及其必要调用链；发现邻近问题时说明影响，除非阻塞本任务，否则不顺带扩张。

## 按需工作流

- 简单、明确、低风险且可快速验证的任务由主线程直接完成，不启动 Skill、subagent、OpenSpec 或完整计划流程。
- 仅当任务多步骤、需求不明确、涉及新功能、系统调试、技术设计、代码审查，或用户明确要求时，才读取 `using-superpowers`。一旦使用，它是该任务唯一顶层方法路由器。
- 仅当仓库存在 OpenSpec 且任务实际涉及规格 artifacts，或用户明确要求 OpenSpec 时，调用 `$openspec-superpowers-bridge`；OpenSpec artifacts 是规格事实来源，不另建第二份正式设计或实施计划。
- 只有准备真实派发 subagent 时才调用 `$codex-subagent-routing`。被派发的 subagent 不再调用顶层路由器，只执行自包含 brief。
- 只有准备执行 commit、worktree、CI、分支收尾、部署或外部副作用时才调用 `$codex-delivery-guardrails`。
- 只有已选择 subagent-driven development、用户禁止 checkpoint commit 且确实需要任务级 review package 时，才使用 `$sdd-no-commit-adapter`。
- 只读且真正独立的调查可以并行；共享工作树默认只有一个写入所有者。父线程必须核对相关 diff 和验证证据。

## 实现与验证

- 优先解决根因，并检查直接相关的异常分支、边界输入、状态一致性、重复执行、资源释放和权限问题。
- 有证据表明问题来自重复职责、多份状态源、新旧逻辑并存或调用链割裂时，进行范围受控的结构性修复；迁移受影响的真实调用方并删除被完全替代的旧实现。
- 不使用假成功、静默异常、无依据默认值、重复刷新、大量硬编码或复制 `new`、`v2`、`fixed` 实现来掩盖问题；也避免无关重构、过度抽象和不必要依赖。
- 测试失败时区分实现、测试假设、环境、依赖和版本问题，不削弱有效测试来适配错误实现。
- 普通修改优先运行静态检查和聚焦测试；仅在跨模块、数据库、权限、依赖锁、发布准备或高风险场景扩大验证。相关代码和环境未变化时，不重复运行相同重型验证。

## Git 与高风险边界

- 未经用户明确授权，不执行 commit、push、merge、rebase、强推、切换或删除分支、部署、重置或丢弃修改。
- 生产部署、真实数据写入或删除、权限或密钥修改、付费或有真实副作用的外部 API、真实通知、价格、订单、支付操作以及其他不可逆动作，执行前说明风险、影响范围和恢复方案并等待确认；用户已明确授权的具体动作无需重复确认。

## 完成说明

完成前检查本次范围的实际修改、相关 diff、可用的 Git 状态和新鲜验证结果。简要说明：

- 检查、修改和删除了什么；
- 实际执行的命令和测试及其结果；
- 未验证内容、未确认事项和残余风险；
- commit、push、PR、merge、archive、部署和外部动作状态。

默认不发送邮件、消息或通知；只有用户在当前任务中明确要求、指定渠道和接收方，且相应工具可用时才执行。
