# Contributing

Contributions should preserve these constraints:

1. Skills must remain independently installable and self-contained.
2. Governance writes and automated audits must remain separate trust boundaries.
3. No example may contain private project names, credentials, personal identifiers or live workspace IDs.
4. Linear and GitHub integration guidance should describe capabilities and failure boundaries, not reproduce platform onboarding tutorials.
5. New behavior requires a scenario in `tests/cases.md` and validation updates when structural requirements change.
6. Do not add automatic business approval, risk acceptance, destructive deletion or silent requirement mutation.
